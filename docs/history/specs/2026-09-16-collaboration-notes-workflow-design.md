# 协作文件体系补全设计（init-project + decision-notes）

**状态：** 已实施
**日期：** 2026-09-16
**目标版本：** v0.9.0
**适用范围：** `skills/init-project/`、`skills/decision-notes/`、`commands/decision-notes.md`

## 1. 背景与证据

`init-project` 此前只铺设两根支柱：根 `AGENTS.md`（外加可选子目录小节）和 `tools.md` / `memory.md` / `memory/archive/` 两张辅助表。审计后认定的缺口：

- **没有记录"因果"的位置。** `memory/archive/YYYY-MM.md` 的 `Events` / `Changes` / `Insights` 三行格式，抄的全部是 git 里已有的事实；代码装不下的唯一信息——当初被放弃过哪些方案、为什么放弃——在该体系中完全缺席。写笔记的动力因此不存在。
- **`memory.md` 的「关键决策（仍有效）」是决策的第二真值源**，与 `memory/archive` 重复，且没有失效标记机制。
- **归一方向与目标相反。** 旧 `SKILL.md` 的 Quality Gate 要求"已被正式文档或当前代码证明失效的旧规则，已经在归一过程中删除"。这会连带删除已经发生的决定，下个会话就会把已被否掉的方案当新方案重提。
- **业务目录无法承载模块规则。** 硬规则 10 要求"只保留一个 substantive 规则文件：`AGENTS.md`"，模块规则只能堆回根文件，正是根文件膨胀的来源。
- **没有触发谓词。** 只有"完成一个完整功能/修复闭环后更新 `memory.md`"这类需要自评的条件，没有可机械判定的非平凡判定表。
- **没有字数预算。** `memory.md` 有 ≤120 行，`AGENTS.md` 反而没有上限。
- **实证：** 本仓库自身有 `AGENTS.md` 和 `docs/`，但没有 `tools.md`、没有 `memory.md`。这套机制在实际使用中从未被跑起来。

同时确认了 `docs/` 只是被"读取"，从未被定义契约：没有去废话守则、没有字数预算、没有事故复盘的独立位置。

## 2. 已确认决策

1. **补成三支柱，每个事实只有一个家。** 根 `AGENTS.md` 管"开工前必须知道什么"；`docs/` 管"现在是什么样"；`.agents/notes/` 管"当初为什么这样"；`docs/postmortem/` 是全仓唯一允许写事故的地方。
2. **拆成两个技能，靠一条单向依赖相连。** `init-project` 铺设骨架并写仓库不变量（一次性）；`decision-notes` 拥有格式、非平凡判定、状态迁移与取代流程（每次改动）。两者都保持 standalone，不进入根/leaf 路由。
3. **`init-project` 不得复述四格模板与非平凡判定表**；`decision-notes` 不得复述协作文件规则。笔记体系的耦合点收敛为 `.agents/notes/AGENTS.md` 这一份仓库运行时契约。
4. **`.agents/notes/AGENTS.md` 是安装投影，不是第二份规范。** 它由 `init-project` 从 `decision-notes/references/notes-contract.md` 的第 4、5 节不变量生成，只写"什么不许做"；写作方法留在技能里。两边冲突时服从仓库那份并在总结里点名。
5. **字数预算改为缺省值。** 具体数字（1,950 / 750 / 2,400 / 1,320 词）来自参考实践，只作缺省；仓库已有自己的预算文件或 CI 阈值时以仓库为准。
6. **退役 `memory/archive/` 月度流水。** 已有文件保留不动、不再追加；仍在生效的因果条目建议迁入 `.agents/notes/`，事故内容建议迁入 `docs/postmortem/`，迁移由用户决定，技能不擅自搬迁。
7. **区分两类内容，处理方式相反。** 失效的**旧规则**在归一中删除；**已经发生的决定**一律不动，只标注被谁取代后移入 `archived/`。
8. **`docs/` 条件归一，不强制新建。** 已有 `docs/` 则归一结构并生成 `docs/AGENTS.md`；只有散落设计文档时只建 `docs/AGENTS.md` 与索引式 `docs/architecture.md` 且不搬动原文件；完全没有则跳过并在总结里说明。

## 3. 所有权边界

| 内容 | 归属 | 形态 |
|---|---|---|
| 全仓常驻军规 | 根 `AGENTS.md` | 3–6 条，每条一行 + 链接 |
| 模块就近规则 | `<子目录>/AGENTS.md` | 作用域内约束 |
| 现状事实、接口契约 | `docs/` | 只写当下，禁变迁叙述 |
| 文档标准与预算 | `docs/AGENTS.md` | 去废话守则 + 缺省预算 |
| 事故与血泪史 | `docs/postmortem/` | 全仓唯一 |
| 因果取舍 | `.agents/notes/` | 四格 + 目录状态 |
| 笔记不变量 | `.agents/notes/AGENTS.md` | 安装投影，不含写作方法 |
| 写作方法、判定表、验收清单 | `decision-notes` 技能 | 唯一真值源 |
| 命令与路径速查 | `tools.md` | 辅助 |
| 当前状态快照 | `memory.md` | 辅助，不含决策节 |

## 4. 被放弃的方案

1. **把笔记规则一起写进 `init-project`，不做第二个技能。**
   - 最强的理由：一个技能就是一套完整体系，没有跨技能边界，不需要单向依赖，也不会出现"装了 A 没装 B"的半成品状态。
   - 为何被否：`init-project` 是一次性命令，只在接入那一刻执行，管不住后续每一次改动。规则写在一次性命令里，命中率就会和退役前的 `memory/archive` 一样归零——它从不缺规则，缺的是每次都执行的触发器。
2. **保留 `memory/archive` 月度流水，只补一个 `Alternatives` 小节。**
   - 最强的理由：改动最小，已有仓库不需要任何迁移，一个月一个文件便于通读全月脉络。
   - 为何被否：月度单文件仍然是并行分支的冲突点（程度低于全局 `INDEX.md`，方向相同）；`Events` / `Changes` 与 git 重复的问题没有解决；把稀缺的因果信息塞进流水账，只会继续被稀释。改为一条决定一个文件、靠目录位置表达状态。
3. **两个技能各自持有一份四格模板。**
   - 最强的理由：两个技能各自自洽，单独复制安装任何一个都能独立工作。
   - 为何被否：两处必然漂移，而且本仓库开发规则明令"规则原文只在一处维护"。单技能自洽的需求改由 `.agents/notes/AGENTS.md` 这份仓库文件满足——它内联了运行时不变量，不依赖技能是否被加载。
4. **让 `init-project` 直接调用或加载 `decision-notes`。**
   - 最强的理由：单一入口，用户只需跑一个命令，不存在两个技能的安装顺序问题。
   - 为何被否：Agent Skills 不支持技能间调用；跨技能相对路径引用会让单独安装失效，也会被"所有相对导航路径必须可解析"的测试卡住。改为"指名 + 仓库运行时契约文件"的弱耦合。
5. **把笔记契约改成 CI 机械门禁（字数、去废话词、四格字段存在性）。**
   - 最强的理由：参考实践里真正让文档不腐化的就是机器校验，靠约定一定会退化。
   - 为何被否：本批不假定目标仓库有 CI，也不在无 CI 的项目里假装有门禁。本批只把预算写成可校验的缺省值并把规则写死，机械校验作为后续独立变更。

## 5. 已知代价

- 技能目录从 10 个增到 11 个，集合打包版本从 v0.8.0 升到 v0.9.0；该版本号与 `evals/results/v0.9-routing-summary.json` 的评测版本号命名空间相近，需要靠文档区分（评测版本描述 root + 八个 leaf 的路由速率，打包版本描述集合构成）。
- 多出一个入口技能，用户需要多理解一个概念（写笔记 vs 铺骨架）。
- `.agents/notes/AGENTS.md`（不变量）与 `decision-notes/references/notes-contract.md`（方法）之间仍存在少量同义表述。这是"仓库内联不变量"与"技能持有方法"的固有重叠，靠"冲突时服从仓库"加契约里显式声明的安装投影关系收敛，不做物理去重。
- 字数预算是缺省值且没有强制门禁，真正生效仍取决于项目自己接入校验。
- `init-project` 的旧规则 10（只允许一份 substantive 规则文件）被放宽为"全仓一份 + 作用域内多份"。这是一个显式的行为变更，已写入 `docs/history/README.md` 的差异表。

## 6. 本批未引入

- 路由评测未覆盖两个 standalone 技能（与 `init-project` 现状一致，`evaluatedSkills` 仍只含 root + 八个 leaf）。
- 未引入 docs 字数与去废话词的机械校验脚本。
- 未迁移任何既有仓库的 `memory/archive` 内容。
- 未新增 `docs/` 之外的过程文档。
