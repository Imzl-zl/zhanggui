## 生效逻辑

### 触发条件
默认高级标准在以下情况自动生效：

✅ **生效场景**：
- 用户未提供品牌指南、设计系统
- 用户未明确要求具体风格（如"简洁"/"极简"/"工具向"）
- 当前是 `Prototype-Assisted` 或 `Design-Owner` 模式
- UI domain 的 model-owned decision node

❌ **不生效场景**：
- 用户明确提供了设计规范 → 完全遵循用户要求
- 用户要求"简洁"/"极简"/"工具向" → 回归保守规范
- `Direct` 模式（已有设计稿） → 按稿件实现
- `Text-Only` 模式 → 不涉及视觉设计

### 优先级规则

```
1. 用户明确规范（品牌、设计系统、具体要求）
   ↓ 无用户规范时
2. 默认高级标准（Awwwards 级）
   ↓ 功能性场景适度降级
3. 通用约束（可用性、稳定性、无障碍）
```

### 场景自适应

| 场景类型 | 艺术性程度 | 示例 |
|---------|----------|------|
| 品牌官网、产品落地页 | 🔥🔥🔥🔥🔥 完全释放 | Hero 区震撼动效、3D 变换、粒子背景 |
| SaaS 产品前台 | 🔥🔥🔥🔥 高度创意 | 视差滚动、实验性排版、流畅动效 |
| B2B 后台管理 | 🔥🔥 适度艺术 | 精致图标、微动效、品质感配色 |
| 开发工具/IDE | 🔥 保守克制 | 清晰层级、高效扫描、最小动效 |

## 核心约束（所有场景强制）

无论艺术性程度如何，以下规则始终生效：

1. ✅ **统一使用 Lucide Icons**
2. ❌ **禁止表情符号**
3. ✅ **控件尺寸稳定**（不溢出、不重叠）
4. ✅ **交互状态完整**（默认、hover、空、加载、错误、禁用）
5. ✅ **桌面和移动端响应式**

## 设计原则速查

### ✅ 鼓励使用
- Lucide 图标系统
- 非对称布局、视差滚动
- 超大标题 vs 精细正文的对比
- 弹簧缓动（spring easing）
- 惯性滚动、视差效果
- 精心设计的渐变、光效、粒子
- 震撼的 hero 区域
- 3D 变换、动态效果

### ❌ 避免使用
- 表情符号（任何场景）
- 手绘 SVG 图标（有 Lucide 时）
- 生硬的线性过渡
- 过度嵌套的卡片
- 单一色相铺满界面（无层次）
- 装饰性但无意义的渐变球（除非是精心设计的视觉语言）

## 验证清单

在交付 UI 原型或设计推荐前，确认：

- [ ] 使用了 Lucide 图标（检查 `lucide.dev` 引用）
- [ ] 界面中无表情符号（🚫 emoji）
- [ ] 有创意手法但不影响可用性
- [ ] 桌面和移动端都可正常交互
- [ ] 所有交互状态都已呈现
- [ ] 符合场景的艺术性程度（官网 vs 工具类）

## 后续建议

### 可选优化
1. **创建视觉模板库**：为常见场景准备 2-3 套预设风格变体
2. **动效预设**：封装常用的弹簧缓动、视差滚动等可复用组件
3. **场景分类指南**：细化不同产品类型的艺术性建议值

### 监控点
- 首次实际使用时，观察 LLM 是否正确理解优先级规则
- 收集用户反馈，调整场景自适应策略
- 如果发现过度艺术化影响可用性，可在覆盖条件中增加更多降级信号
