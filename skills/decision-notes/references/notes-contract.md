# Decision Notes — 契约

本文件是笔记体系的**唯一规则真值源**。`setup-collaboration-files` 只安装仓库不变量，不复述本文件内容；仓库里的 `.agents/notes/AGENTS.md` 只写"什么不许做"。

两者的关系：`.agents/notes/AGENTS.md` 是 `setup-collaboration-files` 从第 4、5 节的不变量生成的**安装投影**，运行时以它为准；本文件额外拥有写作方法、判定表和验收清单。两边冲突时服从仓库那份，并在总结里点名，不静默择一。

## 1. 与非平凡判定

命中任一项，就必须留笔记：

| # | 类别 | 判定口径 |
|---|---|---|
| 1 | 行为 | 用户看得见的功能、顺序、默认值、报错口径；动一个都算 |
| 2 | 架构 | 模块怎么切、怎么连、谁能调谁；想错方向后面全是返工 |
| 3 | 跨文件契约 | 改一边就必须同步改另一边的约定；漏一处就坏 |
| 4 | 流程与工具链 | 构建、发布、脚本、环境变量；跑法一变，换个机器就露馅 |
| 5 | 测试策略 | 什么必须测、什么不测、为什么；漏一个等于白测 |
| 6 | 落盘·网络·配置格式 | 写进文件、发上网的格式和配置项；改了就得安排迁移 |

直接交代码、**不写笔记**的情况：改样式、格式化、打标、不改行为的依赖补丁、常规 CRUD。

补充两条：

- 日后会被重访的决定，同样算非平凡——笔记的价值正是在下一次被重访时兑现。
- 判不准时按"要留"处理。规则的失效方式从来不是写太多，而是永远不写。

## 2. 写作方向

落笔前想清楚这篇守住哪个方向，它决定 `Decision` 和 `Consequences` 的重心：

- **往前看 · 立新规**：通信契约、状态流转、访问边界、不变量。事故复盘补出来的规矩最硬。
- **往回想 · 记妥协**：为某个隐性约束放弃了主流解法。不记，下个会话就会把它当新方案重提。
- **做减法 · 收窄**：裁剪代码、砍 API、退出条件、迁移边界。收窄比扩张更需要理由。

## 3. 四格

| 小节 | 只回答一个问题 |
|---|---|
| `## Problem` | 没写下什么，导致 agent/后来者自己推断出了什么更严的假限制 |
| `## Decision` | 一句话裁定 + 可判定的准入门槛 |
| `## Alternatives considered` | 想过哪些别的路，每条最强在哪、为何被否 |
| `## Consequences` | 换来了什么、付出了什么 |

硬约束：

- `Alternatives considered` 每条**必须先写"最强的理由"**。只列缺点的替代方案是稻草人，前提一变就没人知道该不该重开。
- 替代方案至少一条。写不出被放弃的方案，说明这件事还没到需要笔记的分量，回 Step 2 重判。
- `Consequences` 必须同时有收益和代价。没有代价的决定，通常是没挑过的。
- `Decision` 里的门槛要**可机械判定**，例如"净删除：引包必须能真删掉自己手写的实现、测试和文档"。不写"更优雅""更清晰"这类需要自评的条件——自评条件会被一路评成 false。
- `Status:` 字段必须与所在目录一致；只允许 `proposed`、`implemented`、`rejected`、`archived` 四个取值。
- `implemented/` 里只写已经发生的事实。禁止出现 `## Proposal`、`## 计划`、`## TODO` 这类标题，校验要拦。

## 4. 目录与文件名

```text
.agents/notes/
├── AGENTS.md              # 仓库不变量，由 setup-collaboration-files 生成
├── proposed/              # 待评审
├── implemented/           # 已落地
│   └── process/           # 可选分组，按职责再分层
├── rejected/              # 已否决
└── archived/              # 被取代，永久冻结
```

- 文件名：`YYYY-MM-DD-<kebab-slug>.md`，日期是决定作出或落地的日期。
- 状态**由目录位置决定**，不靠索引文件、不靠标题前缀。
- 需要分组时用子目录（`implemented/process/`、`implemented/architecture/`），不要发明编号体系。

### 严禁总索引

严禁创建 `INDEX.md`、`notes/README.md` 或任何"每篇笔记都要改一行"的汇总文件：

- 两个分支各写几篇笔记，都会去改同一个文件，Git 只能报冲突。
- 索引一旦滞后，它就从"方便查找"变成"错误的地图"。
- 想看什么，看它在哪个文件夹就够了。

单人开发、不开分支时这条无所谓，但不要为了这种场景把整个仓库的习惯定坏。

## 5. 取代与冻结

架构升级或被后续决定取代时，走"新增 + 迁移"，不走"改写"：

1. **旧篇结论不改**：加一行标注被哪一篇取代，移入 `archived/`。
2. **新篇引用旧篇**：写清旧篇还管哪些历史场景、这次升级的全部代价、为什么必须规范化。
3. **迁移恒等边**：`V1→V2→V3` 每代一个独立迁移包，逐代接力；不在主路径里同时支持两种写法，不做双重别名兼容。
4. **`archived/` 永久冻结**：封起来不许改。谁把它改动了，评审立刻报错。

软件版本可以跳，做过的决定不能当没发生过。

## 6. 与相邻目录的边界

| 内容 | 归属 |
|---|---|
| 当前系统怎么运转、接口契约、配置表 | `docs/`（现状真理源） |
| 真实踩过的雷、线上事故、排查时间线 | `docs/postmortem/`（全仓唯一允许写血泪史的地方） |
| 当初为什么这么定、否定过什么、代价是什么 | `.agents/notes/`（本目录） |
| 常用命令、路径、稳定模式 | `tools.md` |
| 当前状态快照 | `memory.md` |

事故复盘产出的规矩，先落成笔记或 `docs/postmortem/` 条目，再提炼成**一行**进根 `AGENTS.md`。不要让战壕故事污染正常手册。

笔记里不写安装命令、使用教程和接口现状——版本一跳就过期。

## 7. 验收清单

- [ ] 四格齐全，且每格只回答一个问题
- [ ] `Alternatives considered` 每条都有"最强的理由"和"为何被否"
- [ ] `Consequences` 里收益与代价都在
- [ ] `Status` 与所在目录一致，取值合法
- [ ] 只写已经发生的事，没有 `## Proposal` / 计划类标题
- [ ] 被约束的代码入口有一行回指注释
- [ ] 旧篇未被改写；本批若是取代，旧篇已标注取代并移入 `archived/`
- [ ] 没有创建任何总索引文件
